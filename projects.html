home-assistant-config · safety interlocks

The projector you must not unplug

My projector's lamp needs its fans after you switch it off, and cutting power during the cooldown shortens the lamp's life. The projector sits on a smart plug that measures current, so the automation can tell "lamp on" from "fans only" from "actually off".

The rule: when a session ends, wait 90 seconds no matter what. Then check the current every 10 seconds, up to 15 times, and open the relay only after two readings in a row at or below 0.06 A. One low reading could be a glitch; two in a row is the fans stopping.

My favorite part is what happens when it can't tell. If the sensor goes unavailable, the code doesn't guess: it leaves the power on. A projector plugged in overnight costs a few cents. One cut mid-cooldown costs a lamp. When you can't verify, fail toward the cheap mistake.

It's one of five hardware interlocks in the repo, all covered by tests. Try to break it in the simulator.

home-assistant-config · sports.py

Touchdown flashes vs. the Zigbee mesh

When the Eagles score, the nine Zigbee bulbs in the basement celebrate. The obvious version flashes green and white. The trouble is that every color change is a command to every bulb, and a fast chant of them can congest a Zigbee mesh: bulbs drop commands, fall out of sync, and the room looks like a broken string of Christmas lights.

So the color never changes mid-flash. The bulbs hold solid Kelly green, rgb(0, 170, 35), and only the brightness moves, between 100% and 15%. A touchdown gets six stadium-cadence surges, a short breath, then two big ones for E-A-G-L-E-S. It ends holding solid green instead of restoring the old scene, because the game's still on.

And yes, Kelly green, not midnight green. I will not be taking questions.

home-assistant-config · theater.py

The tuner code that never worked

Family members watch my antenna TV remotely, through an HDHomeRun with two tuners shared over Tailscale. If both tuners are busy when the Eagles kick off, the basement wins: the automation frees one up and sends a notification.

Except it turned out it never had. The old code called HTTP endpoints that returned 404 and a proxy endpoint that returned 423 Locked. Nobody had hit that exact situation, so nobody noticed. I rewrote it to use the tuner's own TCP control protocol (lockkey force, then channel none), and the notification now says "preemption failed" when the device refuses, instead of claiming success.

Status: it's only been tested against an idle tuner. The real test is the next game day when both tuners are busy. I'll update this when it happens.

home-assistant-config · basement.py

My slowest trip up the stairs took 18.76 seconds

The basement lights know which way you're going on the stairs. The door opens, then the motion sensor at the bottom trips within 18 seconds: someone's coming down. Motion at the bottom, then the door: someone's leaving, so the lights can turn off behind them.

The "leaving" window was 18 seconds too, until the sensor history showed a real, slow, deliberate climb of 18.76 seconds that didn't count. The window is 25 seconds now. Leaving also gets a 20-second grace period that any new motion cancels, so nobody gets blacked out while they're still downstairs. And if someone leaves the door open, closing it soon after motion counts as leaving too.

Calibrating against real sensor data beats guessing, even when the test subject is me.

Good_Morning_Dashboard · FastAPI

A missing notification reads as "all good"

Good Morning Dashboard tells my household when to leave for the train. SEPTA's API has character. The parameter for how many results you want is req3; the one that looks right, top, is silently ignored. Delay text is free-form ("On time", "5 min", "Cancelled", "Suspended", or something else entirely), and the code never treats text it can't parse as on time.

The design rule I'm proudest of: a push that doesn't arrive looks exactly like a push saying everything's fine. So every upstream has a cache, stale data is served but flagged in the message, and if the check crashes outright, it still sends a "check failed" push. Silence is never the answer.

Transfers were the other fun part. When there's no direct train, it plans each leg separately and pairs them, picking the earliest connection you can still make once live delays are counted.
