# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Personal site for a software engineer who is job hunting, served by GitHub Pages from `master` at the custom domain in `CNAME` (mferet.com). A push to `master` deploys within about a minute, and the repo is public. Commits use the repo-local noreply identity (`MFeret11 <MFeret11@users.noreply.github.com>`).

The site is meant to be **fun, not a résumé**: recruiters get work history from LinkedIn or a résumé PDF. The site presents the author's side projects as one of many, none dominating: the basement theater (with an interactive simulator) is one of them, alongside the stories from his public projects, [home-assistant-config](https://github.com/MFeret11/home-assistant-config) and [Good_Morning_Dashboard](https://github.com/MFeret11/Good_Morning_Dashboard). [WeatherTunes](https://github.com/MFeret11/WeatherTunes) (served at mferet.com/WeatherTunes/ from its own repo) has a project card on Stories and the home page; check `~/WeatherTunes/README.md` before describing it.

It's plain HTML, CSS and vanilla JS: no framework, build step, package manager or tests, and no CDN scripts. (The 2016 version used Material Design Lite from `code.getmdl.io`; that CDN died in 2026 and took the whole layout with it, which is why there are no runtime dependencies now.) The only external resources are Google Fonts and a SoundCloud embed on the About page.

## Preview and check

```bash
python3 -m http.server 8080   # then open http://localhost:8080 (or http://<pi-ip>:8080 from another machine)
chromium --headless=new --no-sandbox --hide-scrollbars --virtual-time-budget=8000 \
  --window-size=1280,900 --screenshot=out.png http://127.0.0.1:8080/index.html   # 390,844 for phone; add --force-dark-mode for Movie mode
```

Headless screenshots catch CSS transitions mid-fade, so the simulator can look wrong in a screenshot when it isn't. To check simulator state, load `basement.html` in an iframe from a same-origin harness page, inject `*{transition:none!important}`, click buttons, and read the `#log` entries and `#st-*` status fields (`--dump-dom` works for this). The Pi's Chromium has no emoji font, so emoji render as boxes there but are fine in normal browsers.

## Structure

- Pages: `index.html` (home), `basement.html` (simulator), `commute.html` (Good Morning Dashboard demo), `projects.html` (Stories: the project cards plus an index of the stories, the URL kept from the old site), `stories/<slug>.html` (one page per story, each with a published date, linking up with `../`), `about.html` (day job in one card, music, skiing, and the `#contact` section). `contact.html` only redirects to `about.html#contact` so old links work.
- There are no templates or includes. Each page has its own copy of the `<head>`, header, nav and footer. Changes to shared chrome go in all five pages and every story page, and each page sets `aria-current="page"` on its own nav link. WeatherTunes (`~/WeatherTunes/index.html` and its `styles.css`) carries a copy of the same header with absolute links, so header changes go there too.
- `styles.css` holds everything, organized by section (tokens, base, header, home, stories, about, footer, simulator).
- Every page links `styles.css`, `site.js` (and `basement.js` or `commute.js`) with a `?v=YYYYMMDD` tag. Bump it on all five pages whenever those files change, or browsers keep running the old script against the new HTML and the simulator breaks.
- **Stories:** each story is its own page in `stories/` (title, meta line with a `<time>` published date, the body, then a nav to all stories and the next one). Each has an index card on `projects.html` (same `id` as before, so old `projects.html#id` links still land on it: `projector`, `weather-music`, `weathertunes`, `zigbee`, `commute`, `stairs`) and an entry in `feed.xml` (Atom). Adding a story means all three, plus a link-preview card; story pages get `aria-current` on Stories like `projects.html`.
- **Link previews:** every page (and WeatherTunes) has `og:image` + `twitter:card summary_large_image` pointing at a 1200x630 PNG in `images/og/` (`home` uses a collage of the three demos). Cards come from `tools/og/card.html` via `python3 tools/og/make_cards.py [name ...]` (headless Chromium; titles and summaries live in its `CARDS`). Re-render a card when its page's title or summary changes.
- **Theming:** light is "Daily Driver" and dark is "Movie mode". The tokens live on `:root`; dark overrides sit under `:root[data-theme="dark"]`, plus a `prefers-color-scheme` fallback for no-JS. An inline script in every `<head>` sets `data-theme` before first paint (from `localStorage` or the OS setting), and `site.js` wires the header switch, saves the choice, and fires a `themechange` event.
- **`basement.js`** is the simulator: a single state object `S`; sensor handlers that copy `basement.py` (`doorOpened`, `motionSeen`, `doorClosed`, `stealthStairs`); `sync()`, a copy of `theater_lighting_sync()`; `render()` (pushes state into the inline SVG, the current chart and the page dimmer); and async actions (`walkDown`, `walkUp`, `play`, `togglePause`, `toggleSocial`, `flash`, `endSession`, `spinDown`; projector states are `off` (mains cut), `standby`, `on` and `cooling`). People walk the stairs and fire the door and motion sensors, so the approach lighting comes from the same rules as the real house. There is no caption under the room any more (it changed too fast to read) and no Free play section; the code paths for them stay tolerant of the missing elements (`setText`, `log()` and `rule()` no-op without their elements). `rule()` still records `S.rule`, which the chapter notes read. `RULES` maps each rule to a caption and a permalink into home-assistant-config pinned to a commit (`OLD` by default; a rule's 5th field pins another, e.g. `NEW` for the mmWave rules; `null` file = no link, for the door-only first version that no longer exists in the repo); when the pyscript files change, re-check the line numbers and the pinned commits. The page tells a story with no autoplay: "Why I started", six chapters (1 coming and going, 2 more than one person, 3 during the show, 4 one button per mode, 5 music without the projector, 6 game day), then a "What I learned" summary (step 7) that ends on a link to Stories, not a restart, shown one at a time (`.step`, `data-step`) beside a sticky room, with a chapter nav, Back/Next, and a `#step-N` hash. Each chapter's "More" holds its "See the code" link, pinned to home-assistant-config 8cab0de. Nothing plays before a click: every chapter opens still (3 and 5 start with "Start a movie"), there are no looping animations, and only one "Try it" button shows at a time. Each chapter opens on a problem, lets the visitor see the room get it wrong, then adds the fix. `GEAR` says which sensors are installed: chapter 1 starts door-only, chapter 2 without the mmWave sensor, and `reset(gear)` defaults to everything. Each chapter has two or three sentences on screen, with the longer version in a `<details class="more">`. Entering a chapter sets the room up instantly with no animation (`SETUP`: `reset`, `seatNow`, `showNow`); nothing moves until a button is pressed. Each step's "Try it" buttons (`data-task`) map to `TASKS` (`ok()` says when it can be pressed, `run()` does it, `resets: true` if it starts with its own `reset()`) and get a ✓ when done; `NOTES` reveal a step's closing note (`data-after`) once its moment happens. Keep step text to two or three short sentences. Bumping `epoch` cancels every running action. Long waits run `SPEED` (10x) faster through `sleep()`, which also speeds up the sim clock; flash timings use real time, because they're visual. For headless checks, load `basement.html#step-N` or click `[data-next]` / `[data-go]`, then click `[data-task]` buttons.

- **`commute.js`** drives `commute.html`: a kitchen display (`#k-card`), a phone lock screen (`#p-list`) and a trip plan (`#tp-route`), with the same step layout, chapter nav, `#step-N` hashes, one-at-a-time `data-task` buttons and `data-after` notes as the basement page, but no timers or animation beyond a push sliding in. `amCard()` and `pmCard()` copy the AM and PM commute card templates in `~/ha_config/dashboards/kitchen.yaml` (severity colors from `packages/commute.yaml`); `PUSH` copies titles and bodies from `app/afternoon_check.py` in Good_Morning_Dashboard, including the follow-up rule (push again only when the rank in `SEVERITY` goes up or the delay grows 10+ minutes), the "Late but still connecting" title for a late first train that still connects, and the "If you take a later train" line (`TRIPS.pm.later`, options whose connection clearly works). Follow-ups run until the connecting train leaves, not the first one. The Stories commute story and the demo summary quote SEPTA call volume (about 4,300 to 1,500 calls a weekday) and the test count; update them if those change. The point of the page is the two-line trip through Center City that the SEPTA app can't plan, so a trip plan strip under the screens shows both legs, and `plan()` copies `_plan_connection()` from `app/commute.py` (earliest catchable connection, the -5 minute floor, tight when the buffer is below 0); the "Change at" pills switch the transfer station, which is a setting in the real service, not something it chooses. Lines and stations are real SEPTA ones (Warminster in, Paoli/Thorndale out, Hatboro to Wayne, changing at Suburban Station by default) but must never be the partner's real lines, stations or times, which live only in that repo's `.env`; train numbers and times are made up.

## Keep the simulator and stories accurate

The simulator and the Stories page describe real behavior from the two repos: the approach lighting (door then motion = arriving, motion then door = leaving, the 20 s walk-out check, the 3-minute stair timeout, the gap that chapter 2 shows: before the mmWave sensor, the walk-out shutoff couldn't see someone sitting still on the couch; since home-assistant-config 8cab0de the mmWave cancels that shutoff, and a 30-minute mmWave vacancy rule turns a quiet room off), lighting modes, the 3% pause glow, receiver DSP per mode, the 4.0 s pause debounce, the curtain call (20% for 10 minutes), the 2% 2000 K stair light, Kelly green `rgb(0,170,35)` brightness-only flashes (100%/15%, touchdown and field-goal cadences), the tuner preemption, the Batocera < 0.05 A for 12 s check, and the projector (since home-assistant-config 233242e: session end puts it in standby over HDMI-CEC with mains on, standby ≈ 0.01 A; `play_music` cuts mains only when the projector is already cold, ≤ 0.06 A; the stray-wake guard in `interlocks.py` sends CEC sleep through the TV box when the lamp is lit > 0.5 A for 2 minutes with the theater not in use, retries after 60 s, notifies, and never cuts mains. The old 90 s cooldown with two readings ≤ 0.06 A is manual-only now and isn't in the simulator; the projector story tells it as the first version). When changing them, check the source docs instead of inventing details: `~/ha_config/docs/` (`safety-interlocks.md`, `lighting.md`, `theater-audio.md`) and `~/Good_Morning_Dashboard/CLAUDE.md` on this Pi.

The tuner preemption story was cut from Stories on 2026-10-27 (untested in a real game, and its ntfy alert doesn't send yet). Bring it back only once it has worked during a real game.
